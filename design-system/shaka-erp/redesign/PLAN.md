# Shaka Theme: Apple-refined redesign, task by task

## Context

`shaka_theme` today re-colors Odoo through SCSS variables (`primary_variables*.scss`), exports `--shaka-*` tokens, and adds a pill tab bar, a statusbar stepper and about 15 motion snippets (`transitions/`). Every other surface is still stock Odoo: navbar, app switcher, control panel, lists, forms, kanban, chatter, dialogs, login and settings.

The goal is a **complete redesign inside the existing addon** (same architecture, same token names), using three skills:

- **impeccable:** process and quality gates.
- **ui-ux-pro-max:** design-system generation.
- **apple-design:** HIG and fluid-motion principles.

The work is split into tasks that each run in their own Claude session.

Confirmed decisions:

- **Direction: Apple-refined.** macOS System Settings/Finder feel. Translucent material only on floating layers: menus, popovers, dialogs, command palette, sticky list header.
- **Color:** Apple system blue for everything interactive. SHAKA gold (logo `#B5925F` on black) only for brand moments: logo, login, app switcher, favorites.
- **Type:** the OS system font for Latin (SF Pro / Segoe UI); Vazirmatn limited to Arabic-script glyphs via `unicode-range`.
- **Density:** macOS-compact, about 14px text and 32px list rows.

### Facts the plan depends on (verified in source)

**Environment**

- **Git:** local `dev` was fast-forwarded to `origin/dev` during planning, so `addons/shaka_theme` is in the working tree.
- **Runtime:** Odoo runs locally via `.venv/bin/python ./odoo-bin -c odoo.conf`. `odoo.conf` is valid and points at the live dev-server database; the redesign works only in its own `shaka_design` database.
- **Database:** the local DB (literally named `${POSTGRES_DB}`) has only `web_enterprise` and `en_US`. That's too little to QA a redesign, so Task 0 builds a demo DB.
- **URL:** the web client URL is **`/shaka`**, because core was renamed.
- **Websocket:** running locally without `workers`, the websocket is served in-process on 8069; no nginx involved.

**Tools**

- **impeccable** at `~/.claude/skills/impeccable`, with its binary bundled. Its `detect` already flags 3 bounce easings in `transitions/`.
- **apple-design** at `~/.agents/skills/apple-design`, not linked into Claude yet.
- **ui-ux-pro-max** via the `uipro` CLI. The current `design-system/shaka-erp/MASTER.md` was generated by it.

**Odoo SCSS plumbing**

- The theme's `primary_variables.scss` loads **before** any Odoo `$o-*` exists, so only literal values work there. It also reaches the frontend/login, PDF reports and POS.
- **Bootstrap overrides belong in `web._assets_backend_helpers`**, before `web_enterprise/.../bootstrap_overridden.scss`. That is how enterprise does it (`web_enterprise/__manifest__.py:28-30`). There, `$o-*` values already exist and switch per scheme.
- **Buttons don't come from `$btn-*`.** They are generated from the `$o-btns-bs-override` / `$o-btns-bs-outline-override` maps. Each entry needs all 9 state keys, as literals, in both the light and the dark file. In dark, `$o-white` is `#000`.
- Enterprise forces radius 0 on badges, cards, toasts, pills, form checks, list groups, progress bars and accordions (`bootstrap_overridden.scss:30-39`). Those variables must be set explicitly.
- Not `!default`, so selectors only: `$o-home-menu-*`, `$o-calendar-today-background-color`, `$o-search-panel-width`.
- Keep real colors in `$popover-bg`, `$input-bg`, `$modal-content-bg` and `$dropdown-bg`: Sass color functions consume them, so never `var()` or `color-mix()`.
- **Dark mode:** Odoo appends its own `*.dark.scss` files **after** the backend bundle, so at equal specificity they beat ours. Our surface files have to be re-appended in `web.assets_web_dark`. Glob matches load alphabetically.
- **libsass (0.22)** rejects `rgb(r g b / a)` and mixed-unit `min()/max()/clamp()`. Use `rgba(...)` and `calc()`. Custom properties need `#{$var}`. Write `-webkit-backdrop-filter` by hand, since the backend isn't autoprefixed.
- **Language:** the backend `<html>` has no `lang`, so `:lang(fa)` never matches. RTL is `body.o_rtl` plus rtlcss.

**Token consumers** (these names must never change)

- `shaka_ui_kit`, `category`, `powerbi_portal`, `win_access` and `budget_planning` read `--shaka-muted|border|surface|text|muted-bg|bg`.
- Three addons parse `--acc-collapse` in JS as **ms**.
- JS hooks to keep:
  - `budget_planning_steps.js` uses `.o_notebook_headers [data-name]` / `a[name]`.
  - The theme's own `morph.js`, `popover.js`, `autocomplete.js`, `modal.js` and `dialog_card_resize.js` patch Popover, AutoComplete and Dialog.
  - `statusbar_stepper.xml` extends `web.StatusBarField`.

**Conflicts to clean up**

- `my_debrand/.../debrand.scss` sets `--NavBar-bg-color: #2b3a4a`, and its `login.scss` sets a background.
- `daily_sales_performance` redefines `--shaka-muted` and `--shaka-border`.
- `sales_analysis` leaks `$black`/`$green`/`$muted` without `!default`.
- `jalali_date.css` hard-codes `padding-left`.

**Out of scope, smoke-checked only:** POS, PDF reports, portal/website, Studio and spreadsheet. The palette still reaches POS, reports and the frontend through the primary variables.

## How every task runs

- **One task = one fresh Claude Code session** at the repo root, on branch `feature/shaka-apple-redesign`. Prompt: `Do design-system/shaka-erp/redesign/tasks/task-NN-*.md`. Every task section is self-contained.
- **Skills:**
  - **impeccable** in every task. Its `context` loads PRODUCT.md, DESIGN.md and the surface brief, and its craft floor applies before any edit.
  - **apple-design** for motion, material and type rules.
  - **ui-ux-pro-max** for generation in Task 2 and for lookups: `search.py "<q>" --domain ux|color|typography`.
- **Dev loop:** edit → reload `http://localhost:8069/shaka?debug=assets` in the in-app browser (debug=assets rereads file mtimes). With `dev_mode = xml` (set in Task 0), new files and XML edits need no restart. **Manifest edits still need a server restart (Ctrl+C, rerun).** Python changes need `-u` (command in Task 0). You log in yourself once; Claude never types passwords.
- **Check matrix, one batched round plus at most one confirm round** (impeccable rule): light + dark (avatar menu → Dark Mode) × en_US + fa_IR × 1440 + 768 wide, plus 390 for shell, overlays and login. Screenshots go to `.impeccable/review/<task>/`, which is gitignored.
- **Gates before commit:**
  1. `.venv/bin/python addons/shaka_theme/tests/scss_compile_check.py` passes. From Task 3 on, it compiles the full light and dark chain plus every theme SCSS file, so a typo can't blank the backend.
  2. `~/.claude/skills/impeccable/scripts/impeccable detect --json addons/shaka_theme/static/src` findings are fixed or justified.
  3. No new console errors.
  4. The task is ticked in PLAN.md.
  5. One commit: `shaka_theme: <task title>`.

### House rules (every task; extends MASTER.md)

1. **Variables before selectors.** If an `$o-*`/Bootstrap variable or a `--Component__*` custom property drives it, set that; write selectors only for gaps.
2. Surface SCSS uses only `var(--shaka-*)` tokens (plus `$o-*` inside `bootstrap_overridden.scss`). No raw hex outside `primary_variables*.scss`.
3. Per-scheme tweaks use `@if $o-webclient-color-scheme == dark`, never dark or `data-theme` selectors. No `!important`, except the existing reduced-motion block.
4. **Never rename or remove an existing `--shaka-*` token, `--acc-*` token (ms), or JS hook class.** Add new tokens only.
5. Logical properties only (RTL is `body.o_rtl` plus rtlcss). **No `letter-spacing` on UI text:** Persian data shows up in en_US sessions too, and tracking breaks Arabic-script joining. The system font carries its own tracking.
6. Materials apply only to floating layers, through the `shaka-material($level)` mixin, which carries the fallbacks for reduced transparency, `prefers-contrast: more` and missing `backdrop-filter` support.
7. Motion uses only transform, opacity, blur and clip-path. It is interruptible, critically damped (no bounce), and honors reduced motion.
8. Text contrast ≥4.5:1 and icons/focus ≥3:1 in **both** schemes, measured.
9. No new JS unless CSS truly can't do it. The only planned JS is the optional chart palette in Task 11.
